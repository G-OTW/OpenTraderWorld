## [0.0.7] - 2026-07-25

### Added
- Agent: **personas** — five built-in role-shaped agents (Quant, Portfolio Manager, Day Trader, Researcher, Financial Analyst), each a stance, an explicit refusal boundary and its own shelf of skills. Pick one when you open a chat from the header picker, or switch mid-conversation: the switch applies from the next message and drops a marker into the transcript, so replies stay attributable to whoever produced them. A persona grants **no data access of its own** — that stays with the conversation's MCP token, module-scoped and yours to set, the same envelope whichever persona speaks. Personas that name no provider inherit the assistant's, so they work the moment they exist. All five are editable and resettable from Settings → AI agents → Personas, which also shows the shelf each one will actually get.
- Agent: **19 built-in skills** — Markdown procedures the assistant loads on demand, covering the platform's own traps rather than generic advice: API navigation, memory hygiene, report writing, acquiring market data, running a backtest (with a complete worked settings object, because the engine reports one missing field per attempt and guessing costs a round trip each time), the anti-overfitting protocol, building custom indicators, risk metrics, portfolio review and rebalancing, session prep and review, journal audits, news digests with prompt-injection hygiene, research briefs, source checking, company studies and valuation framing. Only each skill's name and one-line trigger ride in the prompt; the body is pulled when a task calls for it.
- Agent: a persona's **skill shelf is enforced**. The allowlist on an agent now narrows both the catalog it sees and what `load_skill` will load, so a persona cannot reach another's shelf. An agent with no allowlist still sees every enabled skill, as before.
- Backtest: **date-windowed runs.** `from`/`to` on a run (and on the alignment preview) restrict the simulated span, which is what walk-forward validation and regime slicing need — run the same settings over consecutive windows and compare. Accepts `YYYY-MM-DD` or RFC3339; a plain end date covers that whole day. The window is **stored with the run**, so reopening a report or resampling it in Monte Carlo replays the same span instead of silently spreading over the full history.
- Agent: a **wide mode** for the conversation. The thread is sized for prose, which is wrong for the tables the assistant produces — a trial ledger or a stats breakdown needs room. The toggle sits in the chat header and is remembered.
- Agent: **write confirmation.** When the assistant wants to change your data the run pauses and shows the exact call — method, path and body — with Approve and Decline. Nothing is written until you answer, declining is reported to the model as a refusal rather than an error to route around, and walking away times the write out instead of applying it. A persona can be set to auto-approve ordinary writes; **deletions always ask**, whatever that setting says. Endpoints that only compute (a backtest, a Sharpe ratio, a Monte Carlo) never prompt — a confirmation dialog on every calculation is how people learn to click Approve without reading it.
- Agent: a **persona editor**. Create one from blank, duplicate a shipped one and rewrite the copy, edit the prompt and the shelf, or delete one you made. Deleting **keeps its conversations** — they move to the default assistant with a note in each transcript, because deleting a stance is not deleting the work done under it. Built-ins refuse deletion (the app re-creates them on the next restart, so it would only appear to work) and offer reset instead.
- Agent: **export and import** for personas and skills. Any persona exports as JSON with the skill bodies inline, so one file reproduces it on another install; a single skill or the whole shelf export the same way. Import accepts either shape and skips names that already exist. Persona and skill management stays deliberately absent from the MCP catalog, so no agent — and no content an agent reads — can edit a persona or widen a shelf.
- Agent: memories now record **which persona wrote them**, shown in the memory manager and in the index the assistant reads. Memory is one shared store, so without it a constraint the day trader noted about one session reads to the portfolio manager as a standing fact about the whole book.
- Agent: the skills list shows **how many personas hold each skill**, and says so again when you edit or delete one. There is a single catalog shared by every persona, so an edit is never local to the one you had in mind.
- Backtest: **`POST /api/backtest/sweep`** — run a parameter grid server-side and get every trial back. A grid driven by the model was N tool rounds and only the model ever knew how many variants it tried, which is precisely the number that decides whether the best one means anything. Now the trial count is a property of the response. Grid paths reach into arrays (`long.entry.conditions.0.left.period`), so indicator periods are sweepable; capped at 4 axes and 64 trials.
- Backtest: **deflated Sharpe** on a sweep. Alongside the trial table and the spread of trial Sharpes, the response carries the Sharpe the best of N *worthless* strategies would be expected to reach given how much these trials varied. On real BTCUSDT daily bars, the best of eight moving-average crossovers scores 0.59 against a selection bar of 0.70 — the verdict is "no evidence of an edge", which is the answer the maximum alone would have hidden.
- Agent: **provider and model per conversation.** The header picker now switches the model for the thread you are in, not for the whole assistant — run a cheap fast model on a journal review in one tab and the strongest reasoning model on a backtest argument in another, at the same time. A conversation with no choice of its own inherits the persona's, then the agent settings, and the picker shows which is in force. Switching provider drops the previous vendor's model id rather than sending it to an endpoint that has never heard of it. Settings → General still sets what new conversations start with.
- Agent: a **simulation budget per conversation.** Backtests are the one thing an assistant can spend without limit; once the budget is gone it is told to stop searching and report what it has, including how many trials it ran.
- **A centralized data broker for market-data connectors.** A provider account belonged to one module: the same Binance key had to be created twice — once in Historical Data, once in Watchlists — and neither list knew about the other. There is now one list of connectors, each granted to the modules you choose (all of them, or a subset), reachable from three places that are the same screen: **Settings → Data connectors**, the `/connectors` page, and a shortcut button in every module that reads market data. Keys still come from the vault, usage limits still attach per connector, and a module refuses a connector it was not granted — server-side, not just in the picker.
- Visualization: **chart any instrument your connector serves, stored or not.** The chart no longer opens a *dataset*; it opens an instrument. Search a symbol, pick a timeframe, and the bars are drawn whether or not anything was ever downloaded — **nothing is written to your database** until you press Save, which queues the ordinary download job over the window you are looking at, so what you keep merges with whatever was already there instead of duplicating it. What is already stored is read from your database and **never downloaded twice**: only the missing edges of the window go to the provider.
- Visualization: **live is the default view of a current instrument, and it stores nothing.** The live feed is now addressed by instrument rather than by dataset: any symbol a stream-capable provider serves streams its forming candle the moment you open it, whether or not you ever downloaded it. Watching used to require creating a dataset first, which meant a glance at a symbol left a half-empty entry in your catalog. Save it and the *same* feed starts recording its closed bars into the dataset — no second connection, no gap at the handover — so recording is something you turn on, not something that happens to you.
- Visualization: a **Data tab with one search box over every connector** the chart is allowed to use. Type `BTC` and Binance, Kraken, Coinbase, Yahoo, EODHD, Alpha Vantage, Alpaca and Massive answer with their own spelling of the symbol. Under the box, a **Sources** button lists the connectors you own — ready ones only, those still missing a key belong in the connector manager — and **the tick is the permission itself**: the server refuses a connector this module was never granted, so a checkbox that only lived in the browser would have promised what it could not deliver. Providers with no lookup endpoint say so instead of silently returning nothing, and each hit shows whether you already hold it. With the box empty the panel shows two shelves, Recent and Stored, ten rows each.
- Visualization: two display options in the chart settings — a **last-price tag** pinned on the price scale at the latest close (tinted like the candle that produced it, and following the live feed), and **which side the price scale sits on**, left or right. Everything anchored to the scale — its labels, the crosshair value tags, the last-price tag, the drag gutter that rescales it — moves with it.
- Visualization: **why data is missing is always named.** A window that comes back short carries a typed reason — missing credential, connector request limit reached, provider rate limit, unknown symbol, history depth, or the plain start of what the provider serves — shown above the chart while the bars that *did* arrive stay on screen. The connector limit you set is enforced here rather than merely counted, because one click on this page can spend a request.
- Agents can now read the broker: `GET /api/connectors/providers` and `GET /api/connectors` (which connectors exist, which modules they serve, which credentials are set — names only, never values), plus `POST /api/histdata/preview` to look at an instrument without downloading it, `GET /api/histdata/symbols` to find how a provider spells a symbol, and `POST /api/histviz/series` to read a window of bars with the same store-first, gap-fill-only economics the chart uses. Creating a connector and setting credentials stay off the MCP catalog, like every other secret-handling route.
- Demo: the public sandbox can serve **HTTPS on a real hostname**. `OTW_DOMAIN` passes through to Caddy, which issues a Let's Encrypt certificate over HTTP-01 (443 published alongside 80); `OTW_CADDYFILE` plus the new `Caddyfile.demo` instead serves a preissued origin keypair, for the case where a CDN terminates TLS in front.
- Demo: **`OTW_IMAGE_TAG` pins what the sandbox runs.** The demo compose hardcoded `:latest`, so a deploy could neither be reproduced nor rolled back; it now selects a released tag for all three images (default `latest`, so local dev is unchanged), and `reset.sh --init` no longer falls back to building otw-core from source on the host.
- Demo: **`OTW_DEMO_BIND` restricts the published ports to one address**, so a staged demo can stay reachable over a tailnet only until it is deliberately opened.
- Install: **`--yes` / `OTW_ASSUME_YES`** accepts every prompt default explicitly, and **`--wipe-volumes`** resolves stale data volumes in one command. Both are forwarded from `install.sh` to `deploy/setup.sh`.

### Changed
- **The per-module provider settings are gone.** Historical Data's Settings tab and Watchlists' Sources tab were two copies of the same screen over two disconnected lists; both are replaced by a Connectors button that opens the shared broker. Existing connectors keep exactly the reach they had — a Historical Data connector stays a Historical Data connector until you grant it more.
- Agent: the chat **always opens with a conversation ready**, instead of an empty pane on a fresh install. The tools dropdown and the persona picker attach to the open conversation, so with none there was nothing to attach them to.
- Agent: the **tools dropdown is always visible** once a chat is open, even with no token and no external server configured — it reads "No tools" and offers the links that create the first one. Previously it was hidden entirely until something existed, so a new user never discovered that the assistant could reach their data at all.
- Agent: conversation **titles are shorter** (38 characters, cut on a word boundary rather than mid-word), so a long first message no longer fills the sidebar with one entry.
- Visualization: **the chart is driven by hand, not by ECharts' roam.** Dragging animated every step over a fixed 100 ms that cannot be turned off, so a pan nudged the window and stuck; the wheel moved a tenth of a notch per detent and a trackpad barely registered at all. The visible window is now held as bar indices and every gesture writes it directly: drag pans 1:1 with the cursor at one repaint per frame, the wheel zooms anchored under the pointer with the delta normalized across mice, trackpads and pinch, dragging the price gutter scales it by hand (double-click it, or the badge that appears, to go back to auto), dragging the date strip zooms with the right edge pinned, and the keyboard mirrors all of it — arrows pan, Shift pans fast, `+`/`-` zoom, Home/End/`0` jump. The chart also keeps **empty space after the last bar**, so the crosshair tags clear the axis and you can pan past the end instead of hitting a wall.
- Visualization: **the wheel zoom is calibrated per device.** A mouse notch reports a delta twenty times larger than a trackpad tick, so a single constant made one of them jump and the other barely move — a trackpad zoomed 0.7 % per event, which read as broken. The delta now sets a normalized step, floored so a trackpad advances and capped so a flick cannot cross several zoom levels: about 17 % per mouse notch, 4 % per trackpad tick.
- Visualization: the timeframe picker is a **dropdown** instead of a row of buttons — a connector serving a dozen bar sizes filled the toolbar with them.
- Visualization: **changing chart type no longer resets the zoom.** Candles → line keeps the same bars, and used to move the viewport anyway; only a genuinely different series — another dataset, or Renko — rebuilds the window now.
- Visualization: indicators are computed **once per render** instead of three times; the legend used to recompute an entire series just to pick its swatch colour. A redraw now replaces only the series that changed rather than tearing the whole chart down, crosshair tags are batched into a single frame, and the volume bars are split into two series so the per-bar colour callback disappears. Together these are what made toggling one indicator on ten thousand bars stutter.
- Visualization: the legend carries **values at the crosshair** — O H L C and the change, plus each indicator's reading — and falls back to the newest visible bar when the cursor is away, so the readout is never blank. The date axis reads `2024-03-07`, or `03-07 15:04` on intraday data, instead of the raw RFC3339 timestamp.
- Visualization: the **timeframe strip** offers every bar size the connector supports, not only the ones you happened to download, and **keeps the dates you were looking at** instead of dropping you onto “the last 200 bars” of the new series.
- Visualization: **history loads on demand, 1500 bars at a time.** The chart opens on the newest window and puts a button at the left edge of the loaded data; each click walks one slice further back, reusing anything already stored and downloading only the gap. Fetching on scroll was quietly spending a metered API key every time the cursor drifted left — and a market that is simply closed looks exactly like missing history, so the request was repeated forever. When the provider will not serve the slice, the button keeps its place and carries the reason.
- Visualization: one fullscreen instead of two — the in-chart button used the browser's native fullscreen while the toolbar button used an in-app overlay, so the same-looking control behaved differently depending on which one you reached for.

### Fixed
- Agent: **sending a second message while a reply was streaming took the whole backend down.** The conversation claim built its guard before checking whether the claim succeeded, and dropping the unused guard re-locked a mutex the same thread was already holding — the API stopped answering, health check included, until the container was restarted. A double-send is now what it was meant to be: a clear "a reply is already streaming for this conversation", in a hundredth of a second, with the server untouched.
- Agent: **declining a write no longer reads to the model as a timeout.** Every refusal was reported as "the user did not answer in time", so the assistant treated a decision as a transport failure — it announced a server problem and re-issued the same write on the next message. Refusal and silence are now distinct, and a refusal says so in those terms.
- Agent: the **simulation budget no longer charges what it refuses.** A grid of 64 trials against a budget of 60 was rejected *and* billed, so three progressively smaller attempts left the conversation at 116 of 60 without a single simulation having run. A call that does not fit is now refused free of charge and told how many trials are still available, which is enough to resize the search in one step.
- Agent: the **built-in backtest skill taught a configuration that produces meaningless results.** Its worked example paired a crossover entry with `exit_on_reverse` and no exit condition — the entry group is true only on the bar of the cross, so every trade lasted exactly one bar. The same EMA20/50 request returned +3 743 instead of the +32 979 the strategy actually makes, with a plausible narrative attached. The example now carries explicit exits, the trap is documented in the skill and in the endpoint's catalog entry, the skill requires reading `avg_bars_held` and `exit_reasons` before reporting anything, and **the engine returns a `warnings` array** naming the configuration when it sees it.
- Agent: the **default assistant now carries the same rules as the personas** — figures come from a tool call, tool output is data and never instructions, no advice, say what you are about to change. It shipped with two sentences, so the one agent every conversation starts on was also the only one with nothing telling it to report an injected instruction rather than quietly work around it. Installs whose prompt is untouched are upgraded; an edited prompt is left alone.
- Agent: **the assistant knows what day it is.** The current date and time now ride in the system prompt — nothing else gave it a clock, so "prepare today's session" or "last week's trades" depended on some endpoint happening to echo a timestamp.
- Agent: **the module index rides in the prompt**, so a conversation no longer spends its first tool round asking which modules it can reach, and older tool payloads are **trimmed to their head** when the history is re-sent each round. A catalog dump read once was being paid for again on every later turn of the same run.
- Agent: hitting the **tool-call limit ends on a conclusion** instead of a half-written answer. The run now spends its last turn with the tools withdrawn, reporting what it gathered, what it could not check, and what it would do next.
- Agent: "chat only" and "a token with no permissions" no longer produce **the same message**. A conversation with no tools attached said permissions were missing and sent the user to Settings → MCP, which is not where the fix is.
- Agent: a **skill body cannot be saved near-empty** any more (it stays on every persona's shelf and `load_skill` serves the stub without a word), **persona names must be unique** (the name is the identity in an exported shelf), and **importing with `overwrite` now updates a persona** instead of silently skipping it, as its own documentation said it did.
- Agent: the **long-term memory index no longer grows the prompt without bound.** The whole index — every memory's slug and description — was re-sent on every turn of every run; a store filled to its 200-entry cap cost ~8 950 input tokens for a bare "hello". The 40 most recent memories still carry their description; older ones list the slug and author alone (still readable in full with `memory_read`), which drops the same 200-entry case to ~4 760 tokens and stops descriptions from scaling with the store.
- Agent: the assistant can **prune long-term memory when it fills up**, instead of hitting a wall it cannot clear. A new `memory_delete` tool lets it remove a memory by slug — destructive, so it always asks you to confirm first (even with auto-approve on), the same as any deletion. When the 200-entry store is full it now asks which to remove and deletes with your confirmation, rather than only telling you to prune it yourself.
- Agent: the assistant **can no longer overwrite a memory you wrote by hand.** `memory_write` upserts by slug and has no confirmation step, so on a slug collision it silently replaced a user-authored note — content, provenance and all. A hand-written memory is now off-limits to the tool: it refuses and is told to use a different slug or ask you to change yours. The assistant still updates its own memories in place, and you can still overwrite anything from the memory manager.
- Agent: **a model that cannot call tools is usable again.** Such a model refuses the request outright, and since the memory and skill tools are always offered, even a chat-only conversation was dead — with an error blaming the model name, which was correct. The run now replays the turn once without tools and says so in one line, so the conversation works minus the data access.
- Agent: `pick` warns that it drops the timestamps on endpoints returning parallel column arrays — picking `c` off a bars response and counting positions is how the assistant dated a close a month early and reported a 30-day change of −11.7% where the data says +3.7%.
- Backtest: **Monte Carlo is reachable from the agent.** The endpoint existed but was missing from the MCP catalog, so the assistant found the door locked and fell back to pulling the whole trade list and doing the statistics itself — numbers with no tool call behind them, which cannot be checked or reproduced. It is now exposed, with a `view="summary"` shape that returns the percentile bands, risk of ruin and probability of loss without the equity fan, histograms and realized curve: 613 bytes instead of 40 KB on a 557-trade run, and a fixed size no matter how many trades or iterations.
- Agent: the backtest skill taught a **wrong field name** for constant operands (`{"kind":"value"}`), which the engine rejects — it is `{"kind":"const","value":30}`. Every strategy the assistant composed with a fixed threshold failed until it guessed its way out. All four operand kinds and all eleven comparison operators are now documented, including custom indicators, which had no documented way to be referenced from a strategy at all.
- Agent: a tool call whose arguments failed to parse now says so. Both wire formats park unparseable arguments aside rather than dropping the call, which happens when a reply is cut off mid-JSON by the token limit; the call then fell through to a validation error about whichever field looked missing, so the model retried the same truncated call instead of shortening it.
- Agent: the chat now shows **it is working for the whole run**. The streaming cursor was suppressed as soon as a turn carried tool chips, and a fresh turn is only created once text starts flowing again — so the entire tool phase, which is most of a skill-driven run, left the thread blank with no sign that anything was happening. A status line with the run's current phase (thinking, then working) fills that gap.
- Install: **`curl | bash` no longer looked hung.** With no terminal attached, `read` returns non-zero with an empty answer, which the prompt helper could not tell apart from pressing enter — so every question silently took its default, leftover data volumes were kept, and setup then aborted on the Postgres password mismatch it had just caused. Prompts now stop on EOF and print the question along with the non-interactive escape hatch, and the stale-volume abort prints the exact command that clears it.
- Install: **a partial install resumes instead of refusing.** A `deploy/` directory with no `.env` stranded every retry; it is now treated as unfinished work and carried on. A configured install is still never overwritten.
- Visualization: **the wheel zooms the chart again.** ECharts' roam controller installs its own mousewheel handler and calls `preventDefault` + `stopPropagation` on the canvas, so the chart's own listener never ran; it now listens in the capture phase, and a notch nudges the window rather than jumping it.

## [0.0.6] - 2026-07-19

### Added
- **Demo mode** — an opt-in posture (`OTW_DEMO=1`) that turns an instance into a public shared sandbox, so anyone can try the app without installing it. Never enabled implicitly; a normal install is untouched. The API switches to **default-deny**: every request must match an explicit allowlist or it is refused, which means a new module or route stays blocked in demo until someone opens it deliberately (the same philosophy as the MCP catalog). Read-heavy features stay browsable while anything that writes secrets, manages providers or reaches the network is held read-only or closed outright. A public status endpoint drives an in-app sandbox banner with a countdown to the next reset, and the whole database is wiped and re-seeded every 15 minutes. Ships with its own hardened `deploy/demo/` stack (compose file, throwaway env template, `reset.sh`) and a seeded dataset — journal trades, portfolios, watchlists, news feeds, prompts and backtest runs — so the sandbox looks like a used install rather than an empty one.
- Demo: the seeded AI agent runs on a **dedicated free-tier key**, repinned at boot onto a model that key can actually serve that day. The agent reaches its own data through the MCP gateway in-process using a seeded read-only token, while the external MCP endpoint and all token management stay closed.
- Demo: a **welcome disclaimer** that must be acknowledged before exploring — the sandbox runs on a free-tier server with free AI models, so it states plainly that pages and answers can be slow, that AI output may be wrong and is not financial advice, that everything typed is visible to other visitors and wiped every 15 minutes, and that settings and connectors are read-only. Acknowledged once per browser session, so a returning visitor landing on freshly reset state sees it again.
- Demo: the seeded sandbox now covers far more of the app, including a **"Market news" feed** backed by an optional AlphaVantage key (`OTW_DEMO_AV_KEY`) that `--seed-demo` seals into the encrypted feed secrets — never written to the seed SQL or the repo. Left unset, that one feed stays disabled; the Reuters/Fed/ECB RSS feeds need no credential.
- Dashboard: **four new widgets** — Agent (chat with the assistant straight from the dashboard), Economics, Prompts and Watchlist — plus a per-widget configuration panel. Translated across all seven language packs.
- **Agent** — a new module and a sparkles shortcut in the top bar (next to the search) that open a agent chat. Bring your own provider: add one or more of the two supported wire formats — **Anthropic** (Claude Messages API) or any **OpenAI-compatible** endpoint (OpenRouter, OpenAI, DeepSeek, Moonshot, Groq, Mistral, Gemini's compat endpoint, …) — each with its own base URL, API key (write-only, never shown again, encrypted at rest with the app's master key) and default model. Nothing is vendor-defaulted: the empty state asks you to add a provider of your choice. Configure the assistant's system prompt, active provider/model, max tokens and temperature. Replies stream live (Markdown-rendered, with an optional "Thinking" fold for models that expose reasoning), conversations are saved in a sidebar with rename / delete and one-click **Markdown export**, and you can stop a run mid-stream.
- Agent: **tools over your OTW data.** Attach an MCP token to the assistant and its per-module permission levels (Read / Read+write / Full, set in Settings → AI agents) apply **directly** — the token IS the permission envelope, with no second agent-side gate. Dispatch goes through the same in-process gateway as external MCP clients (catalog allowlist, per-module checks, settings/secrets/wipe exclusions; no shell or filesystem access by construction). Tool calls appear inline as collapsible chips showing the arguments and result. Bounded at 15 tool rounds per run.
- Agent: **memory & skills.** Long-term memory — the assistant saves small durable facts (a preference, a stable detail) that persist across conversations; you browse, edit and delete them all in a Memory tab (nothing hidden). Only the index (slug + one-line description) rides in the prompt; full content is pulled on demand. Skills — reusable Markdown instruction sets you define in a Skills tab; their name + description are always in the assistant's context and it loads the full body on demand when a task calls for it (enable/disable per skill). Plus a **rolling summary**: once a conversation grows large, older turns are automatically compressed into a running summary so long chats stay cheap, keeping only the most recent messages verbatim.
- Agent: **in-chat provider & model switcher.** A compact picker in the chat header shows the active provider · model; open it to switch provider or pick a model from the provider's **live model list** (queried server-side — your key never reaches the browser; free text still works for proxies without a list). Changes save instantly and apply to the next message. An "Advanced parameters (JSON)" field in settings passes any extra request field verbatim to the provider (a `null` value removes a key — e.g. `max_completion_tokens` for newer OpenAI models, or dropping `stream_options`).
- Agent: **per-conversation tools.** Each conversation carries its own MCP token, switchable from a tools dropdown in the chat header (the token set in settings is just the default for new conversations). Two conversations can run with different data scopes side by side; the dropdown notes when the selected token grants write/delete, and quick-links to Settings → AI agents (create/manage tokens) and to the MCP store.
- Agent: **MCP store — connect external platforms.** A new full-page section (Agent → Manage servers) to add remote MCP custom servers by URL. Streamable-HTTP only (nothing ever executes locally), auth values encrypted at rest and write-only, a **Test** button that connects and lists the server's tools, and per-conversation checkboxes in the tools dropdown. External tools are namespaced (`deepwiki__ask_question`), labeled with their server, time-boxed, and an unreachable server degrades to a warning instead of blocking the chat — with an explicit injection warning when combined with write access.
- Agent: **clearer errors and a token badge.** Provider failures now read as a plain sentence instead of raw JSON — a rejected API key, a rate limit (with the provider's retry-after when it sends one), a wrong model/base-URL, or a server hiccup each get their own message, shown in a dismissible banner above the composer. A content-filter refusal or a reply cut off at the token limit is surfaced too, instead of an empty turn. The chat header shows a running **token count** for the conversation (input + output), so you can see what a thread is costing at a glance.
- **Vault** — an encrypted secrets store for the credentials the app needs on your behalf (provider API keys, feed tokens…). Items are encrypted at rest with the app's master key and write-only once saved; a shared picker lets any module reference an item instead of pasting the secret again. News feed secrets also accept inline `{{vault.item}}` placeholders, resolved by the scheduler at poll time, so a feed URL or header can carry a key without ever storing it in the feed config.
- **Watchlists** — a new module: named lists of symbols with live quotes, day change and sparklines, reconciled from public sources (CoinGecko / Yahoo) out of the box.
- Watchlists: **custom quote sources.** Create your own provider connectors (Sources view) with their own names, vault-picked credentials and request limits, kept separate from Historical Data's. A list can pin a connector as its default source, and each symbol can override it (follow list / auto / a specific connector); per-item provider tickers (`BTCUSDT`, `AAPL.US`, …) are derived and editable, and quote failures surface per row. Lists with a custom source unlock **5s–30s refresh intervals**, with an explicit know-your-limits warning pointing at Settings → API rate.
- Portfolios: **per-asset trade currency.** Buys and sells were implicitly USD; each asset now declares the currency its operations are entered in. Spot quotes stay USD — cost basis and realized PnL convert at each operation's own date via the journal FX rates, so historical buys keep their historical rate. Form labels follow the asset's currency, and a popover explains where prices come from.
- **One-command install.** `curl -fsSL https://raw.githubusercontent.com/G-OTW/OpenTraderWorld/master/install.sh | bash` — a new root `install.sh` checks Docker is ready, fetches only the `deploy/` directory (no source checkout, no toolchain), and hands off to the guided setup, which pulls the prebuilt Docker Hub images. Options: `--dir` (install directory), `--ref` (branch/tag), `--build` (full source clone + local image build). It refuses to touch an existing install and reattaches the terminal so the setup prompts work under `curl | bash`.

### Changed
- Setup: when volumes from a previous install exist, the "wipe existing data" prompt now defaults to **No** — a headless or absent-minded run can no longer delete the previous database; wiping requires an explicit `y` (declining aborts, since fresh secrets can't open the old database volume).
- **New finance redesign** across the entire frontend: self-hosted Inter + JetBrains Mono, a denser type scale, square corners with no shadows or gradients, separation by hairline rules instead of boxes, and all numerals in mono. The accent is now a single restrained gold, spent only on the active nav item, status dots, the equity curve and keyboard focus — buttons, badges, links and chart series are neutral. Charts drop area fills and vertical gridlines. The default theme accent also moved from indigo to **teal**.
- Backtest: **fixed-quantity sizing now scales with leverage**, matching the retail convention (a leverage of 3 on a fixed size of 1 opens 3 units) instead of leaving the size untouched.
- Settings → Credits is now grouped **by kind of data instead of by module**. The same market-data providers feed quotes, watchlists and historical downloads, so a per-module split repeated most of the list; the new Market data / Economic calendar / Investor portfolios / Instrument reference / FX rates grouping lists every provider the platform can pull from exactly once, configured or not.

### Fixed
- Dashboard: the per-widget configuration gear is reachable in view mode again, and grid filets are drawn as cell outlines instead of overlapping rules.
- Histdata: intraday downloads from Yahoo no longer fail outright when the requested window reaches further back than Yahoo keeps that interval (~30 days for 1m, ~60 for 5m/15m, ~730 for 1h). The start is clamped to the available depth instead of the whole request being refused.
- Demo: the agent composer is no longer blocked on a missing API key. The seeded provider row deliberately carries no key — the shared one lives in the host environment — so the UI now reports the agent as usable when the host supplies it (still only a boolean; the key never leaves the server).
- Journal: cost basis is now genuinely **FIFO** when selected — the setting was accepted but silently computed as weighted average, both server-side and in the trade form's live PnL preview. Capital events on a date with no FX rate queue a pending task instead of quietly skewing invested capital.
- Journal: editing an advanced trade no longer leaves behind exit legs from brackets that were un-triggered.
- Backtest: stop-and-reverse entries were silently skipped under risk-based sizing (the stop price was never passed through). Grid trades now carry their entry fee, so trade stats reconcile with the equity curve. Sizing, exposure and margin checks evaluate marked-to-market equity net of margin already committed, so a portfolio can no longer stack positions past its buying power.
- Backtest: the run report page scrolls on its own instead of being clipped by the app shell (and flows normally when printed).
- TaxCalc: profiles gain a flat-rate override; investing gains with no matching holding-relief tier are taxed as income where the regime defines tiers (US short-term at 24%, not the long-term 15%), and wealth-tax brackets are sorted before slicing so unsorted profiles no longer tax later brackets against the wrong base.
- FX: the catch-up job retries pending dates against the business day on-or-before (ECB coverage from 1999) and re-fetches dates stored with partial coverage.
- Quant: a capital-`M` timeframe suffix now reads as months, closing the `1M` month-vs-minute annualization trap; the efficient-frontier chart no longer clips its y-axis label.
- Agent: only one run at a time per conversation, so interleaved saves can't mispair tool calls with their results; the rolling summary now cuts at a user-message boundary; OpenAI-compatible providers that resend a full tool name no longer end up with it concatenated.
- Notification channels: messages are capped to each platform's limit (Discord 2000, Telegram 4096, Slack 40k) so long payloads truncate instead of failing outright.

### Security
- Login now throttles failed attempts (10/min), removing an unthrottled password oracle in web mode.
- The session cookie carries `Secure` in HTTPS network modes (`lan_https`/`web`) and a `Max-Age` matching the 7-day server TTL; expired sessions are purged on each new login.
- Agent: external MCP tool names are deduplicated within a server too, so a name-truncation collision can no longer dispatch to the wrong tool.

## [0.0.5] - 2026-07-14

### Added
- **Global search** — a search bar in the centre of the top bar (focus it from anywhere with ⌘K / Ctrl K, or `/`). By default it matches names/titles across your installed modules, Resources items and Settings sections; a layers toggle in the field widens it to content titles — Editor pages, Goals, Calendar events, ToDos, Routines, Reminders, Prompts and Community docs (titles only, never bodies). Results appear as you type, grouped by type with the matched text emphasised; arrow keys + Enter (or a click) jump straight there.
- Journal: **PnL Calendar** — a new sidebar view showing the classic month-grid heatmap of daily realized PnL. Each day is a green/red cell whose colour intensity scales to the month's biggest day, with its net PnL and trade count; a weekly-total column runs down the right edge and the header sums the month (net PnL, green/red day split, trades, win rate). Navigate months (or jump to today), and click any day to jump straight to that day's trades. Respects the selected category and the journal's display currency (FX-converted); read-only, no schema change. The daily buckets are also exposed to AI agents through the MCP gateway.
- Journal: **exports** — a new Export button in the module header opens a dialog with two outputs. **Trades CSV**: a spreadsheet-ready file of every trade field (typed columns, computed gross/net PnL, category/strategy names, legs as JSON for advanced trades), scoped to the current category and to all time, a week or a month. **Performance report**: a weekly or monthly report — net PnL, win rate, expectancy, profit factor, fees, avg win/loss, best/worst trade, max drawdown, the equity curve, per-strategy / per-category breakdown tables and the trade log — downloadable as **PDF or Markdown**, with all amounts FX-converted to the journal's display currency.
- **Shared report engine** — one document model (stat cards, tables, bullets, time-series charts) with two renderers: deterministic Markdown and a dependency-free vector PDF (stat-card grid, zebra tables with page breaks, line charts with baseline and axis ticks, page footers). The Journal report and the Backtest run report are both built on it, and saved backtest runs gain a server-rendered **`report.pdf`** endpoint alongside the existing `report.md`.
- Quant Tools: **Monte Carlo** — resample a saved backtest run's realized trade sequence into thousands of alternate equity paths to see how much of the result was luck of ordering. The run is replayed to regenerate its exact trades, then resampled by IID bootstrap or streak-preserving block bootstrap; the result shows an equity fan (p5–p95 / p25–p75 bands with the median and the actual curve), the final-equity and max-drawdown distributions, and headline stats — **risk of ruin** (share of paths that breach a chosen drawdown-from-start threshold), median max drawdown, probability of loss and median final equity. Choose iterations, resampling method, the ruin threshold and the horizon.
- Quant Tools: **Seasonality** — month × weekday heatmap plus by-month, by-weekday and (intraday only) by-hour strips of a dataset's period returns, switchable between mean return and volatility. Positive returns read green, negative red; hover any cell for the value, sample count and win rate.
- Webhooks module: **inbound webhooks** — private URLs any external service can POST to (alerting platforms, monitors, scripts…); each received payload is redirected to a module of your choice, starting with RemindMe (payload → in-app notification, also pushed to your enabled channels). Endpoints carry a 256-bit token in the URL (hashed at rest, shown once at creation), can be enabled/disabled, and keep a per-endpoint delivery log. Payloads are parsed liberally (plain text or JSON with loose field names). The page warns when the current network mode isn't reachable from the internet and points to Settings → Network or a tunnel.
- MCP: AI agents can now **create and manage backtest strategies and custom indicators** — the strategy and indicator creator endpoints (create / update / delete) are exposed through the gateway, gated by read+write permission on the Backtest module. Agents can author a strategy, read it back, and run it end to end.
- Central **API request limits** — declare a limit on any external API the app calls for you and watch it fill up. On a news API source: a checkbox in the feed form sets a request cap (or unlimited-but-tracked) per minute/hour/day/week/month, and the source card in the left pane grows a small progress bar (used / total, colored as it fills, reset each period). On a Historical Data connector: the same limit declaration, displayed as a pie gauge in the connector list and the download picker. Counting happens on real requests (each feed poll, each provider call the download worker makes, retries included); limits are informative only — nothing is throttled.
- Histdata: **named provider connectors** — create as many instances of the same provider as you want, each with its own name, its own encrypted credentials and its own request limit. Existing credentials migrate automatically to a default connector per provider; downloads remember which connector they ran through.

### Changed
- MCP: **finer-grained permissions** — module access now has three levels instead of two: **Read**, **Read + write**, and a new **Full (read + write + delete)**. Delete is no longer bundled into read+write, so an agent can be allowed to create and edit a module's data without being able to delete any of it. Set it per module or apply one level to all modules at once (All read / All read+write / All full). A `DELETE` endpoint is now hidden from an agent's catalog unless its token has Full on that module. **Note:** existing tokens with read+write no longer permit delete — re-edit a token and set the module to Full to restore it.
- MCP: `otw_catalog` is now **two-level** to cut token use — calling it with no argument returns a compact index of accessible modules (label, access level, endpoint count), and passing a `module` lists that module's endpoints. Agents drill into only what they need instead of loading the full catalog.
- Backtest: the result chart stays readable on runs with many trades — entry/exit markers and SL/TP lines are hidden when the visible window is too dense (a "zoom in to see individual trades" hint appears) and reveal themselves as you zoom in. Multi-asset (portfolio) runs get a **dataset picker** at the top-left of the chart to switch which asset's candles are shown, and the trades table is now **paginated** (100 per page).
- Histdata: the download form's provider dropdown is replaced by a **searchable connector picker** — type to filter, each row showing the connector's readiness dot or usage pie, its name, provider and paid tag. The Settings tab is now a full connector manager (add / rename / delete, per-connector credentials, limit editor with live usage and reset time).
